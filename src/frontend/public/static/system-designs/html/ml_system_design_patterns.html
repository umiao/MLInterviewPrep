ML System Design Patterns: Interview Answer Framework

6-Section Template + Priority-Driven State Machine + Failure Mode Analysis

Interview Answer: 6-Section Template (15-25 min)
1. Overview 1-2m
Why this system exists
Business motivation before tech
→
2. Architecture 3-5m
How it works
Components + clear responsibilities
→
3. Dataflow 2-3m
How data flows end-to-end
Include error/retry paths
→
4. Formulas 2-3m
Core algorithms
Whiteboard-derivable, define symbols
→
5. Tradeoffs 3-5m
Why this over alternatives
Compare 2+ options quantitatively
→
6. Defense 5-10m
Under-pressure Q&A
L1/L2/L3 layered answers
Key Signals: Business motivation first | Clear component boundaries | End-to-end data path with latency | Derivable formulas with symbol defs | Quantitative comparison of alternatives | "Why not Y" + "When X breaks"
Common Mistakes: Jump to architecture without "why" | 10 components with 1 sentence each | Only happy path, no error/retry | Formulas without variable meanings | "I chose X because it's good" | Only prepared "why X" not "why not Y"

weighted avg progress_pct

visited set prevents cycles
Trigger Completeness Checklist
Status change
Progress change
Log creation
Child add/remove
Missing any trigger = parent permanently stale
Failure Modes & Fixes
1. Missing Trigger
New "child remove" op added but forgot propagation
-> Parent permanently shows stale status
Fix: Maintain trigger checklist, check on every new op
2. Combinatorial Explosion
State machine uses combinations instead of priority chain
-> Edge cases grow exponentially with new states
Fix: Always use priority chain; O(1) for new states
3. Semantic Ambiguity
[mastered, review] has no clear meaning in combinations
-> Inconsistent UI behavior across components
Fix: Priority model eliminates ambiguity by design
Priority Chain vs Combinatorial
Priority: O(1) per new state
Insert into chain, done
vs
Combinatorial: O(2^n) edges
Every pair needs a rule
